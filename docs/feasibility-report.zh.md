# 《创升纪元 / 暗杀神》Steam 版中文补丁：可行性与可发行性分析

- 本文为中文译本。默认（英文）文档：[feasibility-report.md](feasibility-report.md)。两份不一致时以英文为准。
- 分析对象：Steam 安装目录 `Ascension`（Playdek，《Ascension: Deckbuilding Game》）
- 引擎：Unity 6000.0.58f2，IL2CPP
- 日期：2026-08-18
- 结论：**技术上可行**；应以**外置、可开关**方式交付，**禁止改写安装目录作为唯一形态**。文案优先沿用官方与民间主流译名，缺口再补译并保持同一套术语。

---

## 1. 发行与命名

Steam 数字版官方界面语言仅为英语。中文名在玩家与出版史上有两套，都应在补丁中同时承认：

| 名称 | 性质 | 建议用法 |
| --- | --- | --- |
| **暗杀神** | 2011 年方盒子 365 引进时的主流中文名，维基条目名，早期实体版与玩家口碑 | 术语、卡名、风味文本的主要历史来源 |
| **创升纪元** | 2017 年起米宝海豚取得授权后的系列正式名，后续实体扩展多用此名 | 补丁对外名称、扩展名、较新卡包译名的主要来源 |

补丁对外可写作：**《创升纪元》（又名《暗杀神》）中文语言补丁**。游戏内标题不必强行二选一；设置里可用「简体中文 / 繁体中文」，说明文字同时列出两名。

**版权边界（可发行性）：**

- 这是玩家自用的粉丝语言包，不是官方 DLC，不能打包或传播完整游戏文件。
- 可分发：自译/整理后的 **CSV、术语表、字体授权说明、开关器**。
- 不可分发：从实体卡扫描的整图规则书、官方牌面图片、破解过的客户端。
- 实体中文卡牌文本属于原出版社译文。整理进个人补丁供自己使用，与公开再分发不是同一风险等级；若公开补丁，应尽量基于可核验的公开术语（维基、评测中已引用的译名）+ 自行翻译，并注明来源层级。

## 2. 技术可行性（摘要）

游戏已有本地化管线，这是比多数 IL2CPP 游戏更有利的一点。

| 层级 | 位置 | 形态 | 汉化难度 |
| --- | --- | --- | --- |
| 卡面名/效果/风味 | `resources.assets` 中的 `cards_EN` | CSV，TMP 富文本动态叠字 | 低（不必重绘卡图） |
| 教程 | `tutorial_EN` 等 | CSV | 低 |
| 菜单/弹窗 | Google Sheet 缓存，列：`EN FR PT DE ES PL NL IT RU JP CH` | `CH` 列已预留但全空 | 中 |
| 卡牌逻辑展示字段 | `StreamingAssets/Lua/*_cards.lua` | `display_name` / `effect_text` 等 | 低，但 **`card_name` 是内部 ID，禁止改** |
| 战斗日志 | Lua `string.format("%s gains %d runes")` | 少量格式串 | 低 |
| UI 字体 | TextMeshPro 拉丁 SDF | 无 CJK | **高，必须先做** |
| 规则书 | `rulebooks/rulebook*` | 基本是整图 | 后期可选 |

卡面不是「英文印在图上」，而是 `CARDNAME_*` / `EFFECT_*` 叠在卡图上，例如首字放大：`<size=104>V</size>oid Initiate`。中文需要改排版规则（不宜照搬英文首字母放大）。

语言表已有 **CH / JP 空列** 和设置项 `Key_SelectLanguage`。外置补丁仍应**自己做开关**，不要假设玩家能在空白的 CH 语言项里完成「开/关」——未注入字体时选中文会方框；未注入词库时选 CH 会回退英文。

## 3. 文案策略：先沿用，再补译

### 3.1 优先级（必须遵守）

1. **官方实体中文**（方盒子 365《暗杀神》、米宝海豚《创升纪元》）卡名、效果、关键字。
2. **民间已固化的主流译法**（维基术语、长期评测/百科中的卡名，如「天选者」及其风味「你我皆梦他为梦者」）。
3. 两套官方之间若冲突：早期基础包（CotG–SoS）跟《暗杀神》；2017 年后扩展（GotE 等）跟《创升纪元》；公共关键字（符文/战力/荣誉/放逐）全系列统一，不随扩展改口。
4. 仍无来源的卡包：按已锁定的术语表新译，文风对齐早期官方（效果句短、祈使；风味可文言/诗意，但不另造一套资源名）。

### 3.2 已锁定的公共术语（来自维基/早期官方语境）

| 英文 | 采用译名 | 备注 |
| --- | --- | --- |
| Rune | 符文 | 勿译「符石/魔力」 |
| Power | 战力 | 勿译「力量」（易与万智牌混淆） |
| Honor | 荣誉 | |
| Hero / Construct / Monster | 英雄 / 神器 / 怪物 | Construct 早期官方为「神器」 |
| Acquire / Defeat / Banish / Discard | 获取 / 击败 / 放逐 / 弃牌 | |
| Center Row / Void | 中央牌列 / 虚空区 | |
| Apprentice / Militia / Mystic / Heavy Infantry / Cultist | 学徒 / 民兵 / 秘教士 / 重装步兵 / 邪教徒 | |
| Enlightened / Lifebound / Mechana / Void | 需对照实体牌面后锁定 | 派系名两代中文可能不同，建表时标注来源 |

**粗估可复用比例：**

- 高置信官方文本：CotG + RotF + SoS + GotE ≈ **190+** 张（约 20–25% 卡牌），工作以**转录/校对**为主。

- 低置信、需按术语表新译：Delirium / Deliverance / 部分 Legends / 对不上的 Promo，约 **25–35%**。

没有完整公开的「全系列官方中文卡表」可直接导入；工作量主要在**搜集实体/扫描件/评测引用并建对照表**，而不是从零发明译名。

简繁：简体为主词库，繁体用 OpenCC（台湾/香港用词需人工过关键字：获取/獲得、卡组/牌组等）后再校对。目标是设置里可切 **zh-Hans / zh-Hant**，不是两套完全独立创作。

## 4. 外置、可开关（强制设计）

补丁**不得**以「永久覆盖 `resources.assets` / Lua」为唯一用法。玩家必须能在不重装游戏、不 Steam 校验的前提下关掉中文。

推荐形态：

```text
[补丁目录，不在 Steam 安装树内]
  patch.json          enabled: true/false
                      locale: zh-Hans | zh-Hant
  glossary/           术语表与来源标注
  loc/cards.zh-Hans.csv
  loc/ui.zh-Hans.csv
  loc/tutorial.zh-Hans.csv
  fonts/              CJK TMP 或动态字体（需确认授权）
  loader/             运行时注入（优先）或一键应用/还原
```

**开关语义：**

| 操作 | 行为 |
| --- | --- |
| 打开 | 启动时读取外置词库 + CJK 字体，覆盖显示层 |
| 关闭 | 不注入；游戏与原版英语一致 |
| 切简/繁 | 只换词库与字体子集，不改玩法数据 |

**实现优先级：**

1. 运行时 Hook `LocalizationService.GetTextByKey` / `UILocalizedText`（BepInEx-IL2CPP 或等价注入）。外置 CSV 常驻补丁目录。
2. 若 Unity 6 IL2CPP 注入不稳：对 `StreamingAssets` 与可替换 TextAsset 做**带备份的覆盖**，开关器负责 Apply / Restore。仍算外置（词库不进 Git 游戏树），但关补丁需要跑一次还原。
3. 不优先改 `GameAssembly.dll` 里的硬编码字符串。

Steam 装在 Program Files：写入安装目录需要管理员权限，且「验证游戏完整性」会拆掉覆盖。这也是必须外置/可还原的原因。

联机：只改显示名通常可接受；若服务器比对展示文本，需在打开补丁时测一局。内部 `card_name` 保持英文。

## 5. 工作量评估

按 **1 人、熟悉 Unity 模组、可对照实体/照片** 估算。含简繁校对，不含规则书重绘。

| 阶段 | 内容 | 工时 | 依赖 |
| --- | --- | --- | --- |
| A. 验证 | 导出 CSV；确认卡面走 `cards_EN` 还是 Lua；单卡中文冒烟 | 1–2 人日 | AssetRipper / 十六进制替换试验 |
| B. 字体 | CJK fallback（简繁常用字），接到 TMP | 2–4 人日 | 字体授权（思源黑体/Noto CJK 等） |
| C. 开关器 | 外置目录 + 开/关/简繁；优先运行时注入 | 4–8 人日 | Unity 6 + IL2CPP 工具链是否可用 |
| D. 术语与来源库 | 建 glossary，标注官方/民间/新译 | 2–3 人日 | 实体牌、评测、维基 |
| E. 卡牌文案 | ~2330 条：转录官方 → 核对民间 → 新译缺口 | 10–18 人日 | D；后期扩展偏新译 |
| F. UI + 教程 | ~300 UI Key + ~104 教程句 | 2–4 人日 | 无官方菜单中文，需自译但跟术语表 |
| G. 繁体 | 转换 + 关键字人工 | 2–3 人日 | E/F 简体定稿 |
| H. 测试 | 单人流程、图鉴、教程、开关往返、可选联机 | 3–5 人日 | C 完成 |

**合计：**

| 范围 | 人日 | 日历（兼职约 15h/周） |
| --- | --- | --- |
| MVP：字体 + 开关 + 基础三包卡面（CotG/RotF/SoS）+ 主菜单 | **18–28** | 约 4–6 周 |
| 完整：全卡包简繁 + 教程 + 稳定外置开关 | **26–47** | 约 2–3 个月 |
| 规则书图像汉化 | 另加 5–15 | 可选，不进 MVP |

风险缓冲：Unity 6 资源回写、IL2CPP 注入失败，可能让 C 阶段再加 **1 周**（改走备份覆盖方案）。

**不要做的事（会显著膨胀工期）：** 重绘卡图、改规则书全图、改 `card_name`、做语音、兼容 2019 年旧「中文免安装版」（那是另一客户端）。

3. **V1.1：** 繁体切换；教程。
4. **V2（可选）：** 规则书、边角硬编码句。
