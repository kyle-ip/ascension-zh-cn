# Glossary Maintenance Guide

> 中文版：[GLOSSARY.zh.md](GLOSSARY.zh.md)

This project keeps every **one English → one Chinese** mapping in a single file: the **glossary**. It is the **Single Source of Truth (SSOT)** for every translation in the patch. Whether you are proofreading by hand or generating translations in code, the glossary wins.

## 1. File locations

| File | Purpose |
| --- | --- |
| `glossary/zh-Hans.csv` | **The one editable source.** Edit this directly. |
| `glossary/zh-Hans.report.txt` | Statistical report generated by `glossary_gen.py`. Read-only. |
| `tools/glossary_gen.py` | The glossary's "seeded base" helper. Contains the `SEED_ROWS` constant used for programmatic bulk additions. Duplicates between `zh-Hans.csv` and `SEED_ROWS` are auto-deduplicated by `(en.casefold, scope)`. |

This document only describes the three files above. Together they feed the pipeline `tools/overlay.py → overlay.tsv → BepInEx plugin runtime replacement`.

## 2. Schema (6 CSV columns)

`glossary/zh-Hans.csv` is a standard UTF-8 CSV. **The first row must be the header**:

```csv
en,zh,scope,source,status,notes
```

| Column | Meaning | Example |
| --- | --- | --- |
| **en** | English source (used for case-sensitive exact matches). Rows whose `en` starts with `#` are **section-heading comments** and are skipped by the loader. | `Confirm` |
| **zh** | Approved Chinese translation. Leave blank to mark "untranslated, needs work". | `确认` |
| **scope** | Domain / usage (see §3). The toolchain uses scope for (1) `faction × type` combinators (`Enlightened Hero` → `圣贤英雄`) and (2) auto-generating case variants for exact-match (ALLCAPS / alllower / Capitalized) on 5 sensitive scopes. | `button` |
| **source** | Where the translation came from (§4). | `official-anshashen` |
| **status** | `approved` or `draft`. Only `approved` rows enter the final overlay. `draft` rows are placeholders and never trigger a runtime replacement. Untranslated rows should be `draft`. | `approved` |
| **notes** | Human-readable context / correction rationale / scope notes. Chinese or English is fine. | `P0 delete-game dialog confirm; replaces old ui_runtime junk '加入Friend'.` |

### Section heading comments

Lines whose `en` starts with `#` (e.g. `# 系列`, `# 世界`) are visual groupings only. `tools/glossary_gen.py` will rewrite the file and re-sort rows by scope on every run, so any manual grouping you add by inserting blank lines **will be reordered** on the next run — that's intended.

## 3. Scope list

Think of `scope` as a "where does this string appear in the UI" tag. **If the same English word has two different translations in two different contexts, write two rows** (distinguished by scope). Example:

```csv
"Renown","声望","resource","old","draft","old wrong translation before 2025-08-15 — do NOT activate"
"Renown","名望","resource","new","approved","real ASCL (Ascension: Legendary) mechanic"
```

Note that `_seed_missing` deduplicates by `(en.casefold, scope)`, so only **one row per `(en, scope)` pair** survives. If you want to change an existing row's `zh`, overwrite it in the CSV — do not add a second row.

### Valid scopes

| scope | Meaning | Auto case-variants generated | Faction × type combinator |
| --- | --- | --- | --- |
| `series`   | Series / product names (Ascension, 弑神编年史, 创升纪元) | — | — |
| `world`    | World / character names (Vigil, Arha, Samael, Kor) | — | — |
| `faction`  | The 4 factions (Enlightened / Void / Mechana / Lifebound) and their descendants | — | ✅ paired with `type` |
| `type`     | Card types (Hero / Construct / Monster / Trophy Monster, etc.) | — | ✅ paired with `faction` |
| `resource` | Economy words (Rune / Power / Honor / Renown) | — | — |
| `zone`     | Play zones (Center Row / Void / Discard / Hand / Deck) | — | — |
| `verb`     | Cardplay verbs (Draw / Banish / Acquire / Defeat, etc.) | — | — |
| `label`    | Short headers on card faces / panels (Reward / Fate / Trophy / Reward:) | ✅ | — |
| `button`   | Clickable UI labels (Confirm / Start / Undo / or) | ✅ | — |
| `login`    | Playdek / Asmodee login page (Player Name / Sign Up / Password) | ✅ | — |
| `shop`     | DLC store UI (Promo Pack #6 / Purchase Separately) | ✅ | — |
| `chapter`  | Rulebook chapter headings (What's New / Features / RESOURCES) | — | — |
| `promo`    | Promo / Promo pack names / variants (Promo Cards / Promo Pack 1 non-`#` variants) | — | — |
| `card`     | Specific card proper names (Puggageddon / Defender of Vigil) | — | — |
| `credits`  | Credits page role / department labels (Administration / Produced by) | — | — |
| `ui`       | Other UI phrases / headings (Create Offline Game / Opponent Bids:) | ✅ | — |
| `phrase`   | Entire rulebook sentences / paragraphs (≥1 sentence; usually injected via SEED) | — | — |

## 4. Source priority

Use `source` to track provenance. When two sources disagree, the numerically **lower** number wins.

| source | Meaning | Examples |
| --- | --- | --- |
| 1. `official-anshashen` | 方盒子 365 《暗杀神》 printed rulebooks and wiki terminology (CotG–SoS common core). Core mechanical terms follow this for historical player recognition. | Rune → 符文; Banish → 放逐 |
| 2. `official-chuangsheng` | 米宝海豚 《创升纪元》 2017+ official Chinese releases (GotE/DC/DL onward). Newer mechanics introduced after CotG follow this. | Renown → 名望; Dreambind → 梦缚 |
| 3. `community` | Widely-consolidated folk translations seen on 360 Encyclopedia, 方塔桌游 reviews, BGA/Steam write-ups, and localizer compilations. | Promo Pack → 特典包 |
| 4. `new` | No published Chinese official source; derived by analogy to already-locked-in glossary terms. Subject to revision if a more authoritative source appears. | Deliverance Rulebook → 救赎规则书 |
| 5. `old` | Legacy wrong translation kept for documentation only. Always mark `status=draft` so it is never activated. | (reference) Renown → 声望 (superceded old version) |

**Hard rules**:
- In-game series branding is **always 《创升纪元》**, never the old commercial name 《暗杀神》 or a straight transliteration of "Ascension".
- The 4 factions / Rune / Power / Honor / Banish: **locked for the entire series**, never re-open them even if a newer official release differs. Historical players recognise the older official wording.

## 5. Two ways to maintain the glossary

### Way A: Edit the CSV by hand (90% of day-to-day work)

Good when:
- A new untranslated button appears (e.g. you want `FAQ` rendered as 「常见问题」)
- A better translation is proposed for an existing term
- A rulebook proper noun needs to be locked in once and reused everywhere

```powershell
# 1. Open glossary/zh-Hans.csv in your editor of choice
code glossary/zh-Hans.csv
# Excel / LibreOffice / VS Code "Edit csv" extension all work fine

# 2. Find the row or add a new one, fill all 6 columns (scope matters most)
# e.g.   Confirm,确认,button,community,approved,P0 delete-game dialog

# 3. (Optional but recommended) regenerate report & re-sort by scope
python tools/glossary_gen.py
# Expected output:
#   read existing rows: 458 (comments: 18)
#   seed rows injected (absent before): 0
#   rewrote zh-Hans.csv: 458 data rows
#   derived: exact=426  allow_short(len<=4)=49
#   report → zh-Hans.report.txt

# 4. Rebuild translation layer
python tools/build_zh.py
# → produces overlay.tsv + cards.csv + cards_packed.csv + ui.full.csv

# 5. Deploy to the game (CLOSE the game first!)
python tools/patch.py enable --locale zh-Hans
```

### Way B: Seed programmatic entries (bulk / reusable)

Good when:
- Adding >10 entries of a new scope in one go
- Wanting a new batch of translations to be part of the "always present" baseline
- Don't want to hand-fill 6 columns every time

Steps:

1. Open `tools/glossary_gen.py` and scroll down to `SEED_ROWS = [`
2. Append dict entries with all 6 keys:
   ```python
   {"en": "Puggageddon", "zh": "巴哥末日", "scope": "card",
    "source": "official-anshashen", "status": "approved",
    "notes": "official lua_cards定名; seed so we never lose it from overlay"},
   ```
3. Run `python tools/glossary_gen.py`. It merges `SEED_ROWS` with the current `zh-Hans.csv` by `(en.casefold, scope)`: already-present rows are left alone (your manual edits win), absent rows are appended.
4. Build & deploy the same as Way A: `build_zh.py` → `patch.py enable`.

**Key point**: If `SEED_ROWS` and a hand-edited CSV entry share the same `(en, scope)`, **the hand-edited CSV row wins**. That means Way A and Way B can be mixed freely without fear of clobbering. This is the explicit design goal of the "two-entry" glossary system:

```
SEED_ROWS (programmatic baseline)  ──merge_seed──▶  ┌─────────────┐
                                                     │  zh-Hans.csv │  ←  human proofreads / overrides
Human hand edit                                  ─▶  └─────────────┘
                                                                        │
                                                           derive_glossary_exact()
                                                                        │
                                                                        ▼
                                                   overlay.py → overlay.tsv
```

## 6. Untranslated feedback loop

After you deploy, if English is still showing anywhere, the BepInEx plugin writes every string it failed to translate to:

```
<AscensionGame>/AscensionGame_Data/StreamingAssets/zh-cn/untranslated.tsv
```

It's a 3-column TSV of the form `kind\tsrc\tcontext`.

| kind | Meaning | Processing path |
| --- | --- | --- |
| `K` | Unknown `LocalizationService` key (sample English provided). | Printed only. Manually translate the key in `loc/zh-Hans/ui.csv` or `cards.csv`. |
| `E` | Short English UI strings (≤400 chars). | Default path is `translate_effect` pipeline. Rulebook-looking paragraphs (per `looks_rulebook_body()`) are re-routed to the `L` path instead. |
| `L` | Long rulebook body / DLC store copy (>400 chars, or contains `<sprite>` tags). | Ingested into `rulebook.csv` with blank zh, awaiting a human translation. |

### How to digest a dump

```powershell
# 1. Play through the game, clicking every untranslated surface you can find:
#    all 15 rulebooks, every DLC store page, every popup dialog.
# 2. Quit the game.
# 3. Run ingest. It splits the dump onto two spreadsheets.
python tools/ingest_untranslated.py

# Typical output:
#   no new exact UI strings to ingest
#   appended 37 long strings -> rulebook.csv (total 52, 12 already translated)
#   already covered or skipped: 194
#   missing loc keys: 2
#     Key_FAQ_Header  Frequently Asked Questions
#     Key_Promo_11    Promo Pack #11
```

After the run:

- **Short UI strings** (landed in `ui_runtime.csv`): open the file and check if the auto-translation is acceptable. If not, overwrite `zh` or — better — add `(en, correct zh)` to the glossary as a new row. Glossary is SSOT, so it is always preferable to `ui_runtime.csv` edits.
- **Long paragraphs / DLC / rulebook** (landed in `rulebook.csv`): `zh` is left **intentionally blank**. Open `loc/zh-Hans/rulebook.csv` and translate each one as a **full natural-language sentence**. Preserve rich-text tags exactly as they appear in `en` (`<b>`, `<br>`, `<smallcaps>`, `<sprite=N>`, `<color=#...>`, etc.) and carry them into the matching zh position verbatim.
- **Missing loc keys**: look up the sample English in `loc/en/sheets/Common_Strings.csv` or `Ascension_Cards.csv` to confirm the key, then add the row to `loc/zh-Hans/ui.csv` or `cards.csv`.

Repeat the cycle `play → dump → ingest → proofread → rebuild → deploy` a few times and the remaining English shrinks fast.

## 7. Build pipeline cheat sheet

```
glossary/zh-Hans.csv  ←── glossary_gen.py (SEED_ROWS)
      │
      ▼
tools/overlay.py  ── derive_glossary_exact() ──► exact map
      │                                  ├──► allow_short set
      │                                  └──► faction×type combinators
      │
      ├─ ui.csv (Key_* reverse exact-map)
      ├─ cards.csv / combat_log.csv / tutorial.csv
      ├─ ui_runtime.csv (short UI paragraphs)
      ├─ rulebook.csv (long rulebook/DLC paragraphs)
      └─ extras dict (legacy catch-all)
      │
      ▼
loc/zh-Hans/overlay.tsv     (K rows + E rows)
      │
      ▼
StreamingAssets/zh-cn/overlay.tsv   ← BepInEx plugin reads this at runtime
         │
         ▼
   LocalizationService.GetTextByKey(key)  →  K-row replacement
   TMP_Text.set_text(value)               →  E-row exact replacement
                        (NormalizeUi strips rich-tags before 2nd lookup)
```

Quick command reference:

```powershell
# Re-run glossary report + merge SEED_ROWS only
python tools/glossary_gen.py

# Build everything from glossary through overlay (no deploy)
python tools/build_zh.py

# Build + deploy (CLOSE the game first)
python tools/patch.py enable --locale zh-Hans

# Deploy plugin DLL + overlay only (fast)
python -c "import sys; sys.path.insert(0,'tools'); from bepinex import enable_runtime; enable_runtime()"

# Digest fresh untranslated dump (after a playtest session)
python tools/ingest_untranslated.py
```

## 8. Common pitfalls

| Pitfall | Why it's bad | Correct approach |
| --- | --- | --- |
| Editing `ui_runtime.csv` instead of the glossary for reusable terms. | `ui_runtime.csv` is output of ingest; the same paragraph will re-appear and glossary wins on next run. Collaboration requires a shared SSOT. | Any term you'll ever see again goes in the glossary. `ui_runtime.csv` is for one-off throwaway phrases only. |
| Writing `Player Name,玩家姓名,ui` instead of `...,login`. | Case-variant generation covers both scopes, but scopes should reflect real context. Picking the narrowest scope makes the glossary easier to maintain. | Use the most specific scope. Wrong scope won't break anything — you can adjust later. |
| Explaining a correction in `notes` but leaving `status=draft`. | `draft` rows never activate at runtime! If a translation should ship now, it must be `approved`. | Last step of any proofread pass is verifying `status == approved`. |
| Adding both `Reward:` and `REWARD:` rows because exact match seems case-sensitive. | `merge_seed` keys by `.casefold()`, so the second row gets deduplicated. Case variants are auto-generated by `derive_glossary_exact()` for 5 scopes. | Don't hand-add the uppercase variant. If you debug and the variant is missing, verify the scope is one of the 5 variant-producing scopes. |
| Marking ALLCAPS rulebook headings (`RESOURCE`, `FACTIONS`) as `label` scope. | Rulebook headings are scope `chapter` on purpose: they do **not** auto-generate case variants (which avoids false positives on common words). | Keep them as `chapter` and add the 2–3 actual casings you see in the UI as separate glossary rows (title-case with colon, allcaps, etc.). |
| Running `translate_effect` / `name_lexicon.py` across **rulebook narrative**. | Word substitution destroys natural Chinese sentences, producing "符文为一的两main resources在Ascension" garbage output. | Rulebook body text **always** gets a full human translation, one paragraph at a time. |
